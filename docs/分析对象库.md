# 分析对象库与因子输入

界面选择的是分析对象，不再直接列出同一标的的多份物理数据。对象库由数据库目录、标的主表和显式关联配置构建，不改写行情数据库。

- 股票、ETF按代码关联标的主表；同名不同代码仍是不同对象。
- 同一对象关联各来源的OHLC、成交量、成交额、换手率；ETF通过instrument_id关联份额、份额变化和估算资金流。
- 指数的收盘价、PE、PB、波动率等通过 `config/analysis_objects.yaml` 显式归组。新增跨表关系在该文件声明；不通过模糊名称猜测。
- 未映射的宏观指标保持独立，不同单位的序列不强行合并。

运行流程：对象ID → 关联数据集合 → 所选因子的required字段 → 截止日内可用行情 → 因子引擎。手动分析和雷达共用同一路径。旧数据ID通过目录中的dataset_object_ids迁移到对象ID，旧API请求仍可执行。

分析对象只读标准序列。同一标的在同一复权口径下按日期合并多个来源，同日按优先级选一条，某来源缺日时使用其他来源补齐。OHLCV 始终来自同一条当日记录，不在字段层混拼；每日保留实际来源。不同复权口径仍是独立序列。行情修订可能影响重算结果，这不是保存了当时数据库版本的历史回放。

附属字段按日期左连接到所选行情日，不向前或向后填补，缺少则保留空值。份额等字段保留自己的来源和单位，未经核验的单位不与成交量换算。结果详情展示所有已绑定字段、各自最近有效日期及本因子实际使用的字段。辅助字段的展示日期范围以选中行情为准，不能把某个字段最新日期当作全部字段更新日期。

当前已有因子仍按其声明消费数据：例如MACD需要收盘价、OBV需要收盘价和成交量。归集PE、份额等字段不会自动新增对应估值或资金流因子；后续可在因子注册表中声明所需字段接入。

实现：`app/analysis/library.py`负责对象库与取数，`app/analysis/data.py`负责物理数据适配，`app/analysis/factors.py`负责因子定义。三层相互独立，可继续扩展数据表、对象类别和因子。
