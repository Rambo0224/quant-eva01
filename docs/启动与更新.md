# 双击启动

双击工程根目录的 **Quant.bat**，输入菜单序号并回车：

1. **启动分析面板**：后台启动本工程的服务，自动打开浏览器。不会更新数据；重复选择会复用已启动服务。
2. **更新数据**：可输入截止日，或直接回车沿用现有“前一工作日”规则。节假日请指定最近已完成交易日。更新覆盖 `config/data_sync.yaml` 中全部已启用的数据组。
3. **查看最近更新报告**：显示目标日期、状态、失败数据组和报告位置。
4. **关闭分析面板服务**：仅关闭通过健康接口确认属于此工程的服务，不关闭其他端口服务。
0. **退出启动器**：已经启动的分析面板继续运行。

更新时保留控制台窗口。若本工程面板已启动，更新前暂时关闭服务，更新结束后恢复；浏览器页面刷新即可读取更新后的目录。启动器通过操作锁避免多个菜单同时操作；完整数据流程仍使用其原有互斥锁。

## 严格复用现有数据流程

菜单更新调用链为：

`Quant.bat → app.launcher → update_data.ps1 -Dataset all → python -m datahub.sync run → workflow.run_pipeline`

未指定日期时不额外传入日期，完全使用现有更新模块的默认策略。没有新增获取或入库实现，没有修改 `config/data_sync.yaml`、来源优先级、复权、去重、事务或规范化规则。

完整流程包括：读取现有规则 → 主源/备用源尝试 → 保存实际来源与原始记录 → 对已有有效数据规范化发布 → 保存更新报告。部分数据失败时是否继续、旧数据保留和标准层发布规则都由已有模块负责。

真实报告：`logs/data_sync/latest.json`，历史报告：`logs/data_sync/<run_id>.json`。部分成功或未追平不会显示为全部成功。启动失败、网络错误及详细来源错误按原流程记录；菜单保留本次退出码提示。

## 兼容入口与日志

- `start_quant.ps1` 仍可单独启动面板，现在也会自动打开浏览器。
- `UpdateData.bat`、`update_data.ps1 -Dataset ... -End ... -Symbols ...` 保持原有调用方式。
- 面板服务日志位于 `logs/launcher/panel.out.log` 和 `panel.err.log`。
- 使用工程现有的 Python 虚拟环境，不依赖全局 Python；路径支持中文和空格。数据更新仍按原脚本要求使用 `.venv-win`。
- 默认地址为 `http://127.0.0.1:8600/`。命令行可执行 `Quant.bat panel --port 8601`、`Quant.bat update --end 2026-09-15`；更新时应指定与面板相同的端口。

## 验证

启动器通过独立测试端口验证真实启动、健康检查、重复启动复用及关闭；更新分支使用隔离测试验证完整入口和参数传递、部分失败提示、旧报告识别及服务恢复。安装启动器不会自行执行一次全量联网更新。
