# 面板与更新并行

终端更新不再关闭 8600 服务。获取、原始入库和规范化继续写入 `data/replay.duckdb`，原始层保留。

面板读取 `data/panel/` 下独立且不可变的数据库快照。首次启动在更新锁内生成初始快照；全量或指定数据组更新完成规范化后，检查点落盘、关闭写连接、复制并验证新快照，最后原子替换 `current.json`。单独执行 normalize 命令也会发布快照。获取阶段不发布未规范化数据。

更新期间面板持续读取上一版；发布失败继续提供上一版，同时更新报告记为失败。数据源有缺口但规范化成功时仍发布可用结果，报告保留 partial，不能把快照发布时间理解为所有序列已追平。

每个接口请求固定一个快照版本；新请求自动读取新版本。页面每 5 秒查询 `/api/data-status`，显示更新阶段，新版发布后重新加载目录和监控数据，保留当前选择。

快照约占一个主库的磁盘空间。保留至少两个版本，超过一天的更旧快照会在后续发布时清理；被读进程占用的文件留待下次清理。主库更新仍通过 `datahub.sync` 的 writer_lock 串行化，独立脚本不能绕过该锁同时写库。
