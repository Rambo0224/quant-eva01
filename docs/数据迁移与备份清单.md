# Quant 数据迁移与备份清单

本工程的程序代码可以放在 GitHub，运行数据库和本地凭据通过 U 盘单独迁移。

## 必须复制

从旧电脑复制到新电脑工程根目录下的同名位置：

| 路径 | 用途 | 当前大小 |
| --- | --- | ---: |
| `data/replay.duckdb` | 主数据库，包含原始数据、标准化数据、指标和选择来源记录 | 约 2.04GB |
| `data/*.csv` | 股票池、交易日历、证券状态等更新所需的小型元数据 | 小于 1MB |
| `data/*.json` | BaoStock 日期检查点和请求预算等增量更新状态 | 小于 1MB |

复制后应保持路径为：`quant/data/replay.duckdb`。不要改名，也不要放到 `data/panel/`。

## 需要单独保管的配置

这些文件含有数据源连接配置或令牌，不要提交到 GitHub，但如果新电脑要继续联网更新，需要从旧电脑安全复制到 `config/`：

- `config/mcp_servers.toml`
- `config/comein_mcp.local.env`

如果只做离线分析，可以暂时不复制这两个文件。`config/mcp_servers.example.toml` 是示例文件，代码仓库中已有，不包含真实凭据。

## 不需要复制

以下内容是缓存、快照、备份或测试产物，可以在新电脑重新生成：

- `data/panel/`：面板数据库快照，约 12GB
- `.work/`：标准化备份、测试目录、下载源码缓存，约 2.7GB
- `logs/`：运行报告和日志
- `.venv-win/`、`.venv/`：Python 环境，在新电脑重新安装
- `__pycache__/`、`.pytest_cache/`、`node_modules/`

`data/panel/` 不复制不会丢失主数据；启动或执行一次规范化/更新流程后，程序会按需重新发布面板快照。

## 推荐迁移顺序

1. 在新电脑取得 GitHub 中的工程代码。
2. 安装项目依赖并确认程序能启动。
3. 关闭分析面板和更新程序。
4. 将旧电脑的 `data/replay.duckdb` 复制到新工程的 `data/` 目录。
5. 将旧电脑 `data/` 根目录下的 CSV、JSON 文件复制到新工程 `data/` 目录，并覆盖同名文件。
6. 需要继续联网更新时，再复制两个本地配置文件到 `config/`。
7. 启动分析面板，确认数据日期和指标正常；再执行一次增量更新。

## 迁移前检查

复制数据库前先关闭程序，确保不存在 `data/replay.duckdb.wal`。如果存在 WAL 文件，先正常关闭面板和更新程序后再复制主库。

完整数据库备份只需要 `data/replay.duckdb` 加上 `data/` 根目录的小型 CSV/JSON 元数据，不需要复制当前约 24GB 的整个工程目录。
