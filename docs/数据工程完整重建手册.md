# Quant 数据工程完整重建手册

本文是本工程的数据系统交接规范。另一名 AI 或工程师应能依据本文、代码、配置和单独保管的主数据库，在新的 Windows 机器上重建相同的数据目录、数据源连接、增量更新、规范化、派生指标和面板发布流程。

真实账户、密码、token 和 MCP key 不写入本文或 Git。本文说明它们的文件位置、字段格式、连接流程和安全边界；真实值必须从受控凭据管理系统或旧电脑安全迁移。

## 1. 工程边界

Quant 是用于主观投资辅助的量化指标分析工具。它负责获取行情和宏观数据、统一口径、计算因子、生成多空提示和展示图表；它不负责下单、交易、持仓或自动执行投资决策。

主数据频率是交易日日频。数据库连接统一设置 UTC，业务截止日期按北京时间计算。程序的权威配置在 `config/data_sync.yaml`、`config/indicators.yaml` 和 `config/source_registry.yaml`，代码不能绕过这些配置建立第二套数据流程。

## 2. 重建时需要迁移的内容

从 GitHub 获取 `quant-eva01` 的 `main` 分支，代码包含 `app/`、`datahub/`、`macro_replay/`、`scripts/`、`config/`、`tests/`、`docs/` 和图表模板。

必须从旧机器或 U 盘复制到同名路径：

- `data/replay.duckdb`：主数据库，含原始层、标准层、指标和审计记录。
- `data/` 根目录下的 CSV、JSON：股票池、交易日历、证券状态和增量检查点。

需要联网更新时，另外安全复制到 `config/`：

- `config/mcp_servers.toml`：iFinD MCP 配置和 token。
- `config/comein_mcp.local.env`：进门财经 MCP URL 和 key。

不应进入 Git 或普通工程备份：`data/panel/`、`.work/`、`logs/`、`.venv-win/`、`.venv/`、`__pycache__/`、`.pytest_cache/`、`node_modules/`、数据库 WAL 文件。面板快照、日志和缓存都能重新生成。主数据库路径必须保持 `data/replay.duckdb`。

## 4. 数据库分层

`macro_replay.db.ensure_db()` 使用幂等 DDL 创建或补充表，不删除历史，不主动联网。数据库分三层。

### 4.1 供应商兼容表

- `observations`：宏观、估值、期权、期货和派生指标观测值。
- `equity_daily_bars`：股票和 ETF 原始 OHLCV。
- `etf_share_daily`：ETF 份额、份额变化和估算资金流。
- `market_daily_bars`：指数、黄金和其他行情。
- `raw_payloads`：结构化供应商响应。
- `charts`：图表登记。
- `manual_import_logs`：人工文件导入审计。

### 4.2 raw 原始审计层

`raw.acquisition_batches` 保存每次来源、标的和请求窗口的适配器表；`raw.selected_series` 保存逻辑序列最终选中的实际来源、复权口径、请求范围、最新日期和批次；`raw.sync_state` 保存每个规则的截止日、状态、报告和规则签名。原始层是材料，不要求从历史起点到今天完整。

### 4.3 core 标准化层

- `core.instrument_master` 和 `core.instrument_identifiers`：标的主数据与各来源代码。
- `core.market_daily_bars`：统一的日线 OHLCV，唯一键为标的、日期、频率和复权口径。
- `core.etf_daily_facts`：标准化 ETF 份额事实。
- `core.source_contracts`：来源复权、单位、资产类型和优先级合同。
- `core.data_dictionary`：频率、复权和单位字典。
- `core.data_quality_issues`：被隔离的质量问题。

分析和审计以 core 为权威，不直接把某个供应商原表当成最终数据。

## 5. 来源与获取方式的绑定原则

一个数据源由 source ID、来源合同和 adapter 三部分组成：

1. `config/data_sync.yaml` 的 `sources` 登记供应商、方法、复权、单位、资产类型和优先级。
2. `datahub/sync/source_registry.py` 将 source ID 绑定到 adapter 名称。
3. `datahub/adapters/` 的 adapter 负责请求、解析、字段映射、单位转换和异常类型。

例如 `comein_stock_kline` 必须绑定 `comein_stock_daily`；切换到 `akshare_stock_zh_a_hist_qfq` 时，整体切换到 `akshare_stock_qfq`。不能拿一个供应商的请求方式请求另一个供应商，也不能将两个来源的字段混成一个来源。`validate_market_sources()` 会在同步开始时拒绝没有 adapter 的候选源。

## 6. 当前来源链

单个标的按完整来源模块顺序回退；首选请求最多四路并发，DuckDB 写入仍在主线程顺序执行。

### 股票

Comein `get_stock_kline` -> AKShare `stock_zh_a_hist` -> BaoStock `query_history_k_data_plus(adjustflag=2)`。股票默认管理起点是 `2021-01-01`，前复权口径为 `qfq`。项目排除股票代码 `000016`；指数代码 `sh000016` 是上证 50，不能误删。

### ETF

Comein `get_exchange_fund_quote_history` -> AKShare `fund_etf_hist_em` -> BaoStock ETF 历史接口。ETF 默认起点是 `2010-01-01`，原始口径为 `raw`。

### 指数

AKShare 指数适配器 -> Eastmoney/AKShare 指数历史 -> Comein `searchIndexQuotation`。当前指数是沪深 300、上证 50、创业板 50、科创 50和中证 500。

### 其他数据集

- `configured`：iFinD EDB、交易所官方数据和 Comein EDB；iFinD 失败、为空或未覆盖目标日时切换 Comein。
- `etf_shares`：上交所和深交所 ETF 份额/规模接口。
- `akshare_options`：QVIX、IVIX-50、PCR 成交量和 PCR 持仓量。
- `index_valuation`：Comein 指数 PE/PB。
- `futures`：CFFEX 官方主力合约，缺口时切换 Comein 期货 K 线。
- `gold`：AKShare 黄金接口。
- 派生脚本：融资融券、指数/期货波动率和基差、市场宽度、A 股横截面技术因子。

## 7. MCP、账户和密钥

### 7.1 iFinD MCP

真实配置位置是 `config/mcp_servers.toml`，也可以用环境变量 `OMNISIGNAL_MCP_CONFIG` 指向外部文件。仓库只保留模板：

```toml
[hexin-ifind-ds-edb-mcp]
type = "streamablehttp"
url = "https://api-mcp.51ifind.com:8643/ds-mcp-servers/hexin-ifind-ds-edb-mcp"
auth_token = "REPLACE_WITH_TOKEN"
```

股票、基金和新闻 MCP 使用同样结构，仅 server URL 不同。数据工程主要使用 EDB；股票 MCP 不是全市场历史日线批量接口。重建后应验证 `initialize`、`tools/list` 和目标工具的小窗口结构化返回，不能打印 token。

### 7.2 Comein MCP

`datahub/adapters/comein_mcp.py` 按以下顺序读取配置：本地 `config/comein_mcp.local.env`，再读 Windows 环境变量，最后使用默认 URL。文件格式：

```dotenv
COMEIN_MCP_URL=https://mcp-server-global.comein.cn/mcp-servers/mcp-server-brm/sse
COMEIN_MCP_KEY=用户自己的密钥
```

客户端先 GET SSE 地址，读取服务端返回的 JSON-RPC POST endpoint，再执行 `initialize`、`notifications/initialized`、`tools/list` 和 `tools/call`。返回既可能是直接 JSON，也可能是 SSE 事件。工具包括 `get_stock_kline`、`get_exchange_fund_quote_history`、`searchIndexQuotation`、`futures_kline` 和 `indicatorDataRetrieve`/`get_economic_indicator_data`。

### 7.3 其他凭据

AKShare 当前为公共接口；BaoStock 登录由客户端封装且当前不需要 token；如启用 Tushare，使用环境变量 `TUSHARE_TOKEN`。任何新凭据都必须放在本地文件或环境变量并加入 `.gitignore`，不得写入 YAML、数据库、日志或 Git 历史。

## 8. 标准增量逻辑

更新依据是标准化层，不是联网状态，也不是原始层是否“看起来有数据”。`plan_market_update()` 对每个逻辑标的执行：

1. 查询 core 中该标的和复权口径的最后日期。
2. 已达到目标日：`standardized_current`，不联网。
3. core 落后但 raw 已有合格记录：`raw_ready_for_standardization`，只规范化，不联网。
4. raw 也缺数据：只规划标准化最后日期之后到目标日之间的交易日窗口。
5. 目标日前更早的历史断点不在本次增量范围内，不主动补齐。

北京时间 15:00 前，目标日取前一交易日；15:00 后允许使用当天。单个证券停牌可以单独处理；整个市场未开市则不请求当天。数据不足、空表、越界日期、非法 OHLC、负值和错误单位不会生成信号或覆盖旧数据。

市场接口是单标的接口，因此 `market.max_parallel_requests` 默认 4。并发只用于获取；写库必须顺序进行。供应商连续失败会熔断并切换下一个完整来源模块。

## 9. 获取、入库、规范化和发布

完整流程由 `datahub.sync.workflow.run_pipeline()` 编排：

```text
确定目标交易日
 -> 按 core 最后日期规划缺口
 -> 来源 adapter 获取原材料
 -> 写 raw.acquisition_batches 和兼容表
 -> 校验日期、字段、单位、重复记录和数值范围
 -> 写 raw.selected_series、raw.sync_state、ingestion_runs
 -> 执行本地派生指标
 -> storage.publish() 构建 core
 -> audit_database() 检查标准数据缺口
 -> 复制 data/panel/<uuid>.duckdb
 -> 原子替换 data/panel/current.json
 -> 写 logs/data_sync/latest.json
```

`store_frame()` 会先保存适配器表，再检查日期在请求窗口内、OHLC 有限且逻辑正确、成交量/金额/换手率非负；失败批次进入 `data_quality_results` 和 `ingestion_errors`，旧历史保留。来源选择记录实际 source ID，不能用笼统的“market”代替。

`storage.publish()` 根据 `core.source_contracts` 统一复权、成交量单位、金额单位、日期和证券标识。未经合同和质量检查的数据不能进入 core。

## 10. 派生因子和指标

派生计算读取已入库的数据，不在公式阶段补联网。脚本包括：

- `compute_margin_derived.py`：融资融券派生。
- `compute_index_derived.py`：指数波动率、RSI 等。
- `compute_futures_annualized_basis.py`：期货年化基差。
- `compute_baostock_market_breadth.py`：涨跌家数、涨跌比、涨停跌停和换手率。
- `compute_ashare_technical_factors.py`：均线位置、ATR、动量、反转、RSI、量比等。

指标、序列、参数和图表定义在 `config/indicators.yaml`，分析层在 `app/analysis/`。移动平均、标准差、分位数、背离和排名等因子都需要历史窗口；数据不足时显示数据不足，不生成信号。分母为 0 时不生成信号。

## 11. 面板快照

面板读取 `data/panel/current.json` 指向的只读 DuckDB，而不是读取正在写入的主库。规范化成功后程序执行 checkpoint、复制新快照、只读检查，再原子替换 manifest；旧快照保留最近两代。没有快照时，启动器会在写锁内由主库生成首个快照。

## 12. 安装、启动和更新

```powershell
cd C:\Users\<用户>\Documents\工作台\quant
py -3.12 -m venv .venv-win
.\.venv-win\Scripts\python.exe -m pip install -e .
```

启动菜单：

```powershell
.\Quant.bat
```

完整增量更新：

```powershell
.\.venv-win\Scripts\python.exe -m datahub.sync run --dataset all
```

指定日期、数据集或标的：

```powershell
.\.venv-win\Scripts\python.exe -m datahub.sync run --dataset all --end 2026-09-18
.\.venv-win\Scripts\python.exe -m datahub.sync run --dataset market_stock --end 2026-09-18 --symbols 000001,000002
```

单独规范化和发布快照：

```powershell
.\.venv-win\Scripts\python.exe -m datahub.sync normalize --end 2026-09-18
.\.venv-win\Scripts\python.exe -m datahub.sync status
```

启动器的“更新数据”选项调用 `update_data.ps1`，执行的仍是获取、原始入库、派生、规范化、审计和面板发布这一条标准流程。

## 13. 报告与故障解释

最近报告是 `logs/data_sync/latest.json`。`status=partial` 表示流程已经结束，但某些序列落后目标日或某个派生步骤失败，不等于数据库损坏。重点查看 `datasets[].gaps`、`datasets[].failed`、`derived[].result.failed` 和 `normalization.audit`。

- `standardized_current`：标准数据已到目标日。
- `raw_ready_for_standardization`：无需联网，只需发布标准层。
- `no_aligned_candidate`：目标日没有合格来源记录。
- `dates_not_aligned`：来源成功但仍落后目标日。
- `Source circuit open`：来源连续失败，已切换候选源。
- `exceeded 150s/300s`：隔离子任务超时，旧值保留。

## 14. 维护和新增来源规则

更新前关闭重复的面板或更新程序；锁文件是 `.work/data_sync.lock` 和 `.work/quant_launcher.lock`。备份主库前关闭程序并确认没有 `data/replay.duckdb.wal`。不要手工修改 `raw.selected_series` 来掩盖缺口，也不要直接删除原始批次压缩数据库。

新增来源必须同时完成：在 `data_sync.yaml` 登记 source contract；实现 adapter；在 `source_registry.py` 注册；加入候选链；增加字段、单位、日期、回退和真实小窗口测试。不能只在循环里加一个 provider 分支，也不能把新来源伪装成旧 source ID。

## 15. 新机器验收

1. Python 能导入 DuckDB、pandas、yaml、FastAPI。
2. `data/replay.duckdb` 存在，`ensure_db()` 可打开。
3. 所有市场候选都有注册 adapter。
4. iFinD 和 Comein 的 `initialize`、`tools/list` 和小窗口请求成功。
5. `datahub.sync status` 可返回规则状态。
6. `datahub.sync normalize --end <日期>` 能生成 `data/panel/current.json`。
7. `Quant.bat` 能启动 `http://127.0.0.1:8600/`。
8. 指定标的更新只检查指定标的。
9. 完整更新后报告阶段为 `finished`，所有 partial 项都有可解释原因。
10. 执行 `\.venv-win\Scripts\python.exe -m pytest -q` 通过。

## 16. 安全底线

凭据只存在本机受控文件或环境变量，不进入数据库、报告、聊天、截图、Issue 或 Git 提交。如果 token 曾进入 Git 历史，必须在供应商侧撤销并重新生成；删除工作区文件不能清除已推送历史中的密钥。

更底层的表字段、旧脚本清单和历史设计记录参见 `docs/OmniSignal工程交接说明.md`、`docs/数据获取与规范化模块.md` 和 `docs/面板数据发布流程.md`。
