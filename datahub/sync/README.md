# 固定数据模块 datahub.sync

## 一次运行

工程目录双击 `UpdateData.bat`，或执行：

```powershell
.\update_data.ps1 -End 2026-09-16
# 只处理一组数据（组内候选来源仍按顺序尝试）
.\update_data.ps1 -Dataset market_etf -End 2026-09-16
# Python 入口
.\.venv-win\Scripts\python.exe -m datahub.sync run --dataset all --end 2026-09-16
```

不指定日期时，使用北京时间与官方交易日历确定已完成交易日：15 点后包含当日，之前取上一交易日。日历过期会先补取，无法验证时明确报错；也可显式指定目标日。安装工程后也可使用 `quant-data run`。

## 稳定调用接口

```python
from datahub.sync import run_pipeline
result = run_pipeline(end='2026-09-16', datasets=['market_stock', 'market_etf', 'market_index'])
```

`datasets=None` 表示执行配置中全部启用组。报告包含 run_id、开始/结束时间、datasets（每组尝试、成功来源、缺口）、normalization、failed 和 status。status 是 success、partial 或 failed；部分完成不会冒充全库最新，CLI 返回非零退出码便于外部任务识别。

## 程序职责

- `workflow.py`：固定完整流程、互斥运行锁、逐阶段保存报告；一个组出错仍继续其它组及规范化。
- `service.py`：各组任务、候选源顺序尝试、时间和口径校验、命令行。
- `source_registry.py`：来源模块注册表；每个候选来源绑定自己的获取适配器。
- `worker.py`：按来源契约调用已绑定适配器，并提供远程接口进程隔离和超时边界。
- `storage.py`：来源登记、原始入库、事务、质量及错误记录。
- `core.sql`：代码、单位、价格口径与去重规则，标准层生成。
- `config/data_sync.yaml`：来源契约、候选顺序、数据范围和启用规则。

顺序固定为：读取规则 → 对每个逻辑序列尝试主源 → 不可用则备用源 → 成功保存真实来源 → 全部组尝试结束 → 独立执行派生计算 → 标准化已有有效数据 → 全库存量与配置清单核验 → 保存报告。

数据层继续分离。原始层按来源保留记录和批次；标准层按“逻辑序列 + 日期 + 口径”合并来源，每日只发布一条有效记录并保留当日 `source_id`。优先源覆盖同日备用源，优先源缺日由其他来源补齐；不同复权口径和不同单位不合并。标准化不联网，某组获取失败不阻塞其它组发布，缺失或无效的新记录不覆盖旧有效数据。获取与标准化也可以用 `acquire`、`normalize` 单独执行。

报告自动写到 `logs/data_sync/latest.json` 以及按 run_id 保存的历史 JSON，每一步完成后原子更新。锁存于 `.work/data_sync.lock`，进程退出由操作系统释放。该锁避免完整程序重复运行；直接运行旧脚本仍应避免同时写 DuckDB。

股票/ETF/指数多来源已接入；只登记了单一可验证接口的数据集仍按单源执行，不编造备用源。候选列表只声明 `source`，来源契约必须绑定已注册的 `adapter`，并登记单位、口径和优先级。更新时切换的是完整来源模块，而不是独立的请求方式；缺少绑定的候选源会在运行前被拒绝。

本模块运行依托当前工程源码与配置目录。现有宏观、份额、黄金等采集器通过适配调用复用旧脚本；它们尚未全部重写为无工程依赖的独立发行包。`all_current` 覆盖行情、指标、ETF 份额和其他行情；配置中没有记录的指标、库存里没有刷新规则的数据都会列入问题。只有官方当日证券状态确认的停牌、退市记录才允许豁免，不能仅凭旧日期自行判定停牌。

审计详情位于 `normalization.audit`，逐项列出原始层日期、标准层日期、目标日期、负责规则和状态。历史未知复权口径不伪造转换。日常更新从每个标准化序列的最后日期开始，只检查该日期之后至目标日期的交易日；更早的历史断点不进入日常更新计划。计划区间内标准层缺失而原始层已有对应日期时只执行标准化，只有两层都缺时才请求数据源。原始层是可追溯的输入材料，不以自身历史完整性作为更新目标。只更新子集、空响应和中断后的未尝试日期不会记为全日成功。
