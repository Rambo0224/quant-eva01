# 数据采集与标准化模块

代码位于 `datahub/sync/`，配置位于 `config/data_sync.yaml`。这是独立于分析页面的工程模块。

## 固定流程

1. **获取（acquire）**：按逻辑数据集选择目标证券、时间范围和口径。候选来源按配置顺序逐个尝试。主来源请求失败、返回空数据、截止日期未对齐、历史覆盖缺失或价格校验失败，切换到下一个兼容来源；一个来源成功后立即停止这组尝试。来源内有有界重试、45 秒单请求超时和连续失败熔断。
2. **原始存放**：保留实际成功来源及失败尝试。入库以来源和时间范围隔离，失败不能覆盖已有数据。备用源成功不算整个数据集失败，也不要求备用源与主源同时更新。
3. **规范化（normalize）**：独立执行，不访问网络。在一个事务中将各数据集已有有效记录规范化到 `core`；其他数据集获取失败不阻塞发布。未获取新记录的序列保留历史数据，结果通过 stale_series 明确列出尚未达到目标日期的行情序列。

股票的前复权序列使用完整管理窗口重新获取、替换；不能将新复权基准的几天行情拼到旧基准历史后，也不能用不复权行情冒充前复权。

当前 AKShare 股票范围为库内已登记的 40 个股票代码；全市场不复权数据由 BaoStock 规则覆盖。要扩大前复权覆盖范围，可将 `akshare.stock_scope` 改成 `all`。可用 `--symbols` 重试指定股票，但不会将整个数据集的其它缺口忽略掉。

## 命令

在工程根目录执行：

```powershell
# 第一步：分别获取，或用 all 顺序执行所有启用的获取规则
.\.venv-win\Scripts\python.exe -m datahub.sync acquire --dataset akshare_stock --end 2026-09-15
.\.venv-win\Scripts\python.exe -m datahub.sync acquire --dataset akshare_etf --end 2026-09-15
.\.venv-win\Scripts\python.exe -m datahub.sync acquire --dataset akshare_index --end 2026-09-15
.\.venv-win\Scripts\python.exe -m datahub.sync acquire --dataset all --end 2026-09-15

# 查看每组结果；详细错误与日期缺口保存在数据库中
.\.venv-win\Scripts\python.exe -m datahub.sync status

# 第二步：只进行标准化；其它数据集缺口不阻止有效数据发布
.\.venv-win\Scripts\python.exe -m datahub.sync normalize --end 2026-09-15
```

未指定截止日时保守使用前一工作日，不推测当日收盘数据已经发布。遇到市场节假日应显式指定最近已完成交易日。发布检查采用严格日期对齐；停牌、退市或低频序列尚未单独配置豁免时会报缺口，不伪造新数据。

Dashboard 的统一刷新已接入同一模块：获取全部规则 → 规范化发布可用记录 → 获取全部成功时计算派生指标及渲染。获取存在失败仍会发布其它可用标准数据，但不运行旧版依赖原始表的派生计算。旧股票脚本 `fetch_akshare_equity_bars.py` 是兼容入口，也走同一规则。

## 存储边界

- `raw.equity_daily_bars` 等是旧 `main` 来源表的兼容视图，保持现有采集器可用。
- `raw.acquisition_batches` 保存本模块收到的适配器 DataFrame 和请求。`representation=adapter_frame`，不冒充供应商原始 HTTP 响应；历史 raw_payloads 不补造。
- `raw.selected_series` 保存每个逻辑证券序列最终选中的实际来源、请求范围和批次。
- `raw.sync_state` 保存数据集就绪状态、截止日、缺口及原始表签名。
- `ingestion_runs`、`ingestion_errors`、`data_quality_results` 保存批次、每次换源失败和异常。
- `core.instrument_master`、`core.instrument_identifiers` 统一代码；600000.SS、600000 和 600000.SH 映射为同一证券 ID。指数的交易所不能套用纯股票代码推断规则。
- `core.market_daily_bars_by_source` 保留各来源通过质量校验的记录；`core.market_daily_bars` 是量化程序唯一使用的标准序列，按标的、日期和复权口径从多源中选一条。优先源的缺失日由备用源补齐，每条标准记录保留实际 `source_id`。同日不同复权口径保留独立记录。
- 日期使用 trade_date，成交量统一为股/份，金额为 CNY，换手率为百分数（1 表示 1%）。AKShare 股票、ETF 的手数乘 100；BaoStock 保持股/份。
- `core.observations` 和 `core.other_market_daily_bars` 为旧标量及其他市场查询的快照兼容接口；`core.etf_daily_facts` 单独存 ETF 份额。
- `mart.charts` 保留应用产物登记。现有派生计算脚本仍通过兼容 main 表工作，新的标准查询不应读取 main 的一次性回填表。

**已知口径待核验**：历史 Yahoo 数据没有可靠复权标记，保留在 raw 并排除出标准行情；ETF 份额的原供应商单位标记为待核验，不擅自按倍数转换。初版 main.instrument_master、main.market_daily_bars_core、main.etf_daily_facts 为旧迁移产物，已停用；规范接口是 core schema。

## 固定程序入口（新增）

整个过程现在可一次执行：双击根目录 `UpdateData.bat`，或运行 `./update_data.ps1 -End 2026-09-15`。Python 入口为 `python -m datahub.sync run`，模块 API 为 `datahub.sync.run_pipeline`。

完整运行带互斥锁和逐阶段报告；候选来源顺序尝试是程序内部逻辑，无需人工切换。每组获取失败不阻止其它组及标准化，运行报告明确区分 success/partial/failed。详见 `datahub/sync/README.md`，报告位于 `logs/data_sync/latest.json`。
